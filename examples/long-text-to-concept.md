# 示例：长文本转概念卡

## 输入

一份关于“复杂项目如何管理上下文”的章节材料，包含定义、问题、方法和案例。

## 处理过程

1. 登记标题、作者、章节和页码。
2. 按标题拆分内容。
3. 区分概念定义、机制解释和案例。
4. 为“上下文窗口”“检索”“压缩”建立候选概念。
5. 对每个概念保留原文位置。
6. 生成概念卡，标记为“待确认”。

## 输出摘要

- 内容解决的问题：复杂任务中信息太多，模型无法稳定使用全部上下文。
- 核心概念：上下文窗口、检索、压缩、优先级。
- 待确认项：不同模型的具体限制不能只依赖章节中的旧数据。
- 可复用结果：建立一张带来源的概念卡，并链接回章节。
